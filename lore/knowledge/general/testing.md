# Planner testing standard

The planner's tests come in five layers:

1. **Pure domain tests** for readiness, progress, the two delivery rules, placement and front-matter parsing, against copies of real records. No I/O.
2. **Repository tests** against a real PostgreSQL per run: `mise run test` (`scripts/test.sh`) starts one PostgreSQL 16 and every test gets a database of its own, cloned from a template its migration set's first test builds by running the committed migrator (`crates/reeve-testdb`). A test run without `REEVE_TEST_DATABASE_URL` (a bare `cargo test`) starts a container per test instead. Tests that control the server itself (`health.rs` stops it, `backup_restore.rs` runs `pg_dump` inside it) always get a container of their own. In-memory fakes hide transaction and locking behaviour, which is what these tests exist to check.
3. **API tests through the router**, covering the token kinds, with the OpenAPI snapshot (`UPDATE_SNAPSHOTS=1 cargo test -p reeve-server --test openapi_snapshot` once, commit the result). The webhook (`crates/reeve-server/tests/webhook.rs`, signed fixture deliveries) and the import and export endpoints (`tests/import_export.rs`) are tested the same way. The offline export is tested through the built binary (`tests/offline_export.rs`, `CARGO_BIN_EXE_reeve-server`), and the backup procedure by `tests/backup_restore.rs`, which runs the README's `pg_dump`, `createdb` and `pg_restore` inside the test container and compares rows, sequences and the export before and after. `mise run script-test` (and CI) runs `scripts/backup.sh` and `scripts/restore-rehearsal.sh` against a fake `docker compose` (`scripts/tests/fake-compose.sh`), and `scripts/tests/skill-smoke.sh` sources the skill smoke's functions to pin its safety logic.
4. **A CLI end-to-end run** of the acceptance test (`mise run acceptance`) against a fixture repository, and the fake-Jira import (`mise run import-test`, `crates/reeve/tests/jira_import.rs`): `reeve import jira` against a real server and an in-test axum fake Jira serving the committed fixtures in `crates/reeve/tests/fixtures/jira/`. It runs a failed fetch (nothing written), the switch off (nothing requested from Jira), a rehearsal (nothing written, comments read for stories, bugs and tasks only), an apply where one create fails validation (its comment never sent, the rest created), an apply that resumes it, and an apply after an issue changed in Jira (everything existing, nothing updated), and checks the `--json` shapes, the grandfathered states, the comment provenance and that no `override` entry is written.
5. **A Playwright smoke** (`mise run web-smoke`, the CI `smoke` job) across the planning view, the board, the story drawer, the decisions view, the override prompt, live updates over the event stream and the signed-out redirect. `scripts/web-smoke.sh` builds the client and both binaries with `--features reeve-server/static-oidc`, starts the server on `127.0.0.1:7475` against a fresh database (`DATABASE_URL`, which must be empty, or a recreated `reeve_smoke` database in the compose Postgres), seeds the fixture through the CLI and runs `web/tests/smoke.spec.ts`. The tests sign in through the browser against the static provider; no cookie is injected. Run `cd web && npx playwright install chromium` once.

Plus the isolation lint test, `mise run isolation-test`, which proves the lint fails on every bypass shape.

Plus the skill smoke (`mise run skill-smoke`, the CI `skill-smoke` workflow): Lorekeeper's planning skills drive the planner through the `reeve` CLI, and their scenario tests replay a fake of it. `scripts/skill-smoke.sh` builds both binaries with `--features reeve-server/static-oidc`, starts the server on `127.0.0.1:7476` against a database it creates under a unique name (on the compose Postgres, or on the server an allowed `DATABASE_URL` names, whose own database it never writes) and drops on exit, issues an admin automation token, builds a household with one accepted record, and runs Lorekeeper's `reeve-real-server` and `reeve-reference` tests from `LOREKEEPER_DIR`: every command of `references/reeve-cli.md`'s *Commands* table runs against the server and the fake, and the fields the skills read must exist with the same JSON types on both. A skipped, todo, cancelled or failing Lorekeeper test fails the script, and so does a run reporting fewer tests than the script's floor or a TAP stream with no summary. Reeve's own build and tests never need Lorekeeper (kb/ADR-0005 R5).

Plus the workflows: `mise run script-test` runs `scripts/tests/workflows.sh`, which checks that `release.yml` sets `defaults: run: shell: bash` at workflow level (pipefail on every `run:` block) and that no job or step overrides it, and `scripts/tests/ci-needs-rust.sh`, which pins ci.yml's Rust path classifier and the wiring that still runs lint and test when the classifier fails.

Plus the sign-in path: the Google adapter is tested against an in-process fake OpenID provider (`reeve_identity::FakeIssuer`, compiled only under `static-oidc`) that signs RS256 ID tokens with openidconnect's own encoder, checks `client_secret_basic`, PKCE S256 and single-use codes, and rotates its key set on request. `crates/reeve-identity/tests/fake_issuer.rs` pins the fake itself; `tests/google_oidc.rs` pins each claim and signature check of `finish` (issuer, audience, expiry, nonce, signature, PKCE and client authentication), the key-rotation retry and its rate limit, and the metadata refresh, through `make_google_oidc_for_tests` on the production refresh windows and a `TestClock` the tests advance (no sleeps); `crates/reeve-server/tests/auth_web.rs` (`through_the_google_adapter`) signs an admin and a member in through `/auth/login` and `/auth/callback` with the real adapter and checks that an unverified and an unlisted email are refused. Keys are generated per process; none is committed. No test contacts Google: the test factory refuses a non-loopback issuer and gives the adapter an HTTP client with no proxy that resolves no hostnames and refuses, before sending, every request that is not http to a loopback IP (discovered `jwks_uri` and `token_endpoint` included).

**Container-backed tests are never skipped.** A test that needs PostgreSQL starts it (or fails; with `REEVE_TEST_DATABASE_URL` set, a server it cannot reach fails it, never a quiet fallback); it does not return early, carry `#[ignore]`, or pass when the database is absent. The same holds for the smoke: no `test.skip`, and the script fails when the server, the database or the browser is missing. Reason: a skipped test reports green while checking nothing, and the layers that matter most are the ones that need the database.
